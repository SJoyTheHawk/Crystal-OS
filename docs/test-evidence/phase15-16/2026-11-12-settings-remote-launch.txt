Remote Launch while Settings is open — 2026-11-12

Device report (firmware 0.12.14, no corrected firmware flashed yet):
Launch from the browser while Settings is open did not close Settings and did
not leave Status Dashboard selected behind it. The user clarified that the
required baseline is switching the selected app behind Settings; closing
Settings automatically is optional.

Cause found in source:
Remote Launch sent a raw Brookesia START but left the Settings return target
at the previously selected app. Closing Settings explicitly restored that
previous selection. Sending an LVGL event alone also did not prove the app
actually became active.

Correction:
Use start_card(index, false), which verifies the active app and maintains the
shell selection/persistence. After success, point the Settings return target
at the launched app. Keep Settings visible. Log successful background launch.
Unknown targets and failed starts retain the prior Settings return selection.
